# אפליקציית "יעד סודי": אפליקציה ספונטנית ליציאות, מסמך עיצוב

שם עבודה: **סודי** (זמני, ייקבע בהמשך)
תאריך: 2026-11-25
סטטוס: טיוטה לאישור

## 1. כוונה ולמה

אנשים צעירים רוצים לצאת ולא יודעים לאן, או שלא בא להם להחליט. האפליקציה
**מחליטה בשבילם וההחלטה היא הפתעה**. המשתמש נותן כמה רמזים (או שלא נותן
כלום), האפליקציה בוחרת מקום אחד קרוב ומזמינה אותו בעצמה. המשתמש מקבל
"משימה": מתי לצאת, כמה זמן נסיעה, מה ללבוש ובערך כמה זה יעלה. השם של
המקום נשאר סודי עד ההגעה, ובדרך מגיעים רמזים.

הקסם הוא **ההפתעה**, לא ההשוואה בין אפשרויות. לכן הסגירה (הזמנה ותשלום)
צריכה לקרות בלי שהלקוח יראה את שם המקום.

טון: צעיר, ספונטני, סלנג עברי קליל, אימוג'י. עברית בלבד, RTL, מובייל.

## 2. מטרות, לא־מטרות, אנטי־מטרות

**מטרות**
- מסלול אחד חלק: "בא לי לצאת" ← יעד סודי מוזמן ← ניווט ← רמזים ← חשיפה בהגעה.
- בחירה רנדומלית לגמרי, או מכוונת: מספר אנשים, תקציב, מרחק, וייב, קטגוריה.
- הזמנה אוטומטית בשם הלקוח, בלי שהוא נחשף לשם המקום.
- בנייה צעד אחרי צעד: כל שלב (ראו סעיף 7) הוא מוצר שעובד בפני עצמו.

**לא־מטרות (בשלב הזה)**
- אפליקציה נייטיב בחנויות (אולי בהמשך, React Native עם אותו קוד).
- רשימות תוצאות, השוואות וביקורות. יש תוצאה אחת.
- רשת חברתית מלאה (פיד, חברים). "חברתי" כרגע = יציאה בקבוצה ושיתוף החוויה.
- כיסוי ארצי מושלם. מתחילים במטרופולין תל אביב.

**אנטי־מטרות (כישלון גם אם "עובד")**
- הפתעה שמאכזבת: מקום סגור, לא כשר למי שביקש כשר, לא נגיש, דירוג נמוך,
  מעל התקציב.
- דליפת היעד לפני ההגעה: SMS או מייל אישור מהמסעדה ללקוח, שם המקום
  בניווט, התראה שחושפת.
- מקום מוזמן שבסוף לא מחכה ללקוח (הזמנה "שנכשלה בשקט").
- הקלדת כרטיס האשראי של הלקוח באתרים של צד שלישי.

## 3. אילוצים

- **אין עסק רשום עדיין.** בינתיים משתמשים בפרטי קשר זמניים של האפליקציה
  (מייל וטלפון ייעודיים). כל הפרטים האלה נמצאים בקונפיגורציה בצד השרת
  ומוחלפים בקלות כשיוקם עסק.
- **אין API ציבורי** לאונטופו, Tabit, רשתות קולנוע או חדרי בריחה.
  אוטומציה דרך הדפדפן (Playwright) כנראה מנוגדת לתנאי השימוש ועלולה
  להיחסם. זה סיכון מקובל לבטא סגורה, לא לסקייל. הפתרון לטווח ארוך הוא
  שותפויות.
- **Stripe לא זמין לעסק ישראלי.** תשלומים בעתיד יעברו דרך סולק ישראלי
  (Cardcom, Grow, Tranzila).
- **PWA:** זיהוי הגעה ורמזים לפי מיקום עובדים רק כשהאפליקציה פתוחה.
- **Google Places API** עולה כסף לפי שימוש, והמפתח חייב לשבת בצד השרת.

## 4. גישות שנשקלו

**פלטפורמה**
| גישה | יתרון | חיסרון |
|---|---|---|
| **PWA (נבחר)** | הכי מהיר לבנות ולשנות, בלי חנויות, שולחים לינק | זיהוי הגעה רק כשהאפליקציה פתוחה |
| React Native | רמזים והתראות ברקע | איטי יותר, חשבונות מפתח, אישורי חנות |
| אב־טיפוס עם נתונים מדומים | זול, מהיר להדגמה | לא מוצר אמיתי |

המשתמש בחר PWA.

**חשיפה**: גלגל מזל (חשיפה מיידית) / יעד סודי / רמזים. המשתמש בחר
**יעד סודי עם רמזים**.

**הזמנה**
| גישה | יתרון | חיסרון |
|---|---|---|
| לינק לאונטופו בלבד | עובד היום | הלקוח מזמין בעצמו, וההפתעה נהרסת. נפסל |
| **סוכן AI / Playwright מזמין בשם הלקוח עם פרטי האפליקציה (נבחר)** | שומר על ההפתעה, אפשר להתחיל מיד | ToS, חסימות, שבירות |
| API רשמי בשותפות | יציב וחוקי | תלוי בספקים, לוקח זמן. **יעד ארוך טווח** |

המשתמש בחר בסוכן אוטומטי. ההחלטה שלי: מנוע ההזמנות בנוי עם **מתאמים
מוחלפים** (adapters), כך ש-API רשמי יחליף את Playwright בלי לשנות את
שאר המערכת.

## 5. החוויה (מה המשתמש רואה)

1. **פתיחה ראשונה:** שם פרטי (לשולחן), ופילטרים קבועים של "לא בשבילי":
   כשרות, טבעוני/צמחוני, אלרגיות, נגישות, ו"בלי אלכוהול". בלי סיסמה.
2. **"בא לי לצאת":** כפתור ענק אחד = הכל רנדומלי. מתחתיו, אופציונלי:
   כמה אנחנו (1–10), תקציב לאדם (₪/₪₪/₪₪₪), מרחק (הליכה / עד 15 דק' / עד
   30 דק'), מתי (עכשיו / עוד שעה / שעה ספציפית היום), וייב (רגוע / אנרגטי /
   רומנטי / חברים), וקטגוריות להוצאה.
3. **"מחפשים לכם משהו..."** אנימציה, ובזמן הזה המנוע בוחר ומזמין.
4. **כרטיס משימה:** "המשימה שלכם: לצאת עד 20:10 ⏱️ · 14 דק' נסיעה · תלבשו
   נוח 👟 · בערך ₪120 לאדם · שולחן על השם 'דנה' ל-4". כפתורים: "יאללה,
   נווטו אותי", "לא בא לי" (עד 2 פעמים ביציאה, ומבטל את ההזמנה הקיימת),
   ושיתוף לחברים ("דנה לוקחת אתכם להפתעה 🤫").
5. **ניווט:** כפתור פותח Waze או Google Maps ל**נקודת הטעיה**, נקודה במרחק
   150–300 מ' מהיעד, בלי שם, רק קואורדינטות.
6. **רמז בדרך:** רמז ראשון מיד, ורמז שני כשמתקרבים (כ-1 ק"מ) או אחרי חצי
   מזמן הנסיעה, כשהאפליקציה פתוחה. הרמזים נכתבים על ידי Claude לפי נתוני
   המקום ("יש פה משהו שבוער 🔥", "תחפשו דלת ירוקה").
7. **חשיפה:** בנקודת ההטעיה, או בכפתור "הגעתי", מתגלה היעד עם אנימציה:
   שם, תמונה, הוראות הליכה ופרטי ההזמנה. אם האפליקציה הייתה סגורה, החשיפה
   קורית כשפותחים אותה.
8. **אחרי:** "איך היה?" בשלב אחד (👍/👎 + "עוד כאלה" / "פחות כאלה"),
   שמשפיע על הבחירות הבאות.

## 6. ארכיטקטורה

```
[PWA: React + Vite + TS]  ──HTTPS──▶  [שרת Node (Fastify) על VPS]
  מיקום, UI, ניווט, רמזים                ├─ מנוע בחירה  ──▶ Google Places API (New)
  localStorage: פרופיל/העדפות             ├─ מחולל רמזים ──▶ Claude API
                                          ├─ מנוע הזמנות (תור עבודות)
                                          │    ├─ NoBookingNeeded (בר, גלידה, תצפית)
                                          │    ├─ OntopoPlaywrightAdapter
                                          │    └─ ManualAdapter (התראה למפעיל: טלגרם)
                                          └─ SQLite: יציאות, הזמנות, סטטוסים
```

- **Frontend:** React + Vite + TypeScript, PWA (manifest + service worker), RTL
  בעברית, מובייל־קודם. בלי חשבונות: מזהה מכשיר אקראי ב-localStorage.
- **Backend:** Node + Fastify + SQLite. רץ על VPS (ייתכן Hostinger) כי
  Playwright צריך דפדפן אמיתי. כל המפתחות (Google, Anthropic) ופרטי הקשר
  הזמניים נמצאים ב-env בשרת.
- **מנוע בחירה:**
  1. Nearby Search לפי מיקום, רדיוס וסוגים מהקטגוריות.
  2. סינון: פתוח בשעה המבוקשת, דירוג ≥ 4.2 עם ≥ 50 ביקורות, רמת מחיר לפי
     תקציב, ו"לא בשבילי".
  3. ניקוד: התאמת וייב, מרחק, "עוד/פחות כאלה" וחידוש (לא מקום שכבר היה).
  4. הגרלה משוקללת. **שומרים 3 גיבויים בדירוג.**
- **מנוע הזמנות:** לכל מועמד בוחרים מתאם. אם ההזמנה נכשלת או אין מקום,
  עוברים אוטומטית לגיבוי הבא, והמשתמש לא יודע על זה. מסך "מחפשים" ממתין
  עד 60 שניות. אחרי זה נבחר מקום שלא דורש הזמנה, כדי שתמיד תהיה הפתעה.
  סטטוסים: `pending → booked | failed | not_needed`.
- **פרטי הזמנה:** שם פרטי של הלקוח + טלפון ומייל **של האפליקציה**, כדי
  שאישורים ו-SMS לא יגיעו ללקוח. קוד SMS (אם נדרש): בשלב הבטא המפעיל מקבל
  אותו בטלפון הזמני ומזין דרך פאנל/טלגרם. אוטומציה לזה תיבנה בהמשך.
- **ביטול "לא בא לי":** המתאם חייב לתמוך בביטול. אם לא, נשלחת התראה
  למפעיל לבטל ידנית.

## 7. שלבים (צעד אחרי צעד)

1. **שלב 1, לולאת ההפתעה (בלי הזמנות):** PWA, מנוע בחירה עם Google Places,
   כרטיס משימה, נקודת הטעיה + ניווט, רמזים מ-Claude, חשיפה, משוב. מוגבל
   לקטגוריות שלא צריך להזמין בהן (בר, בית קפה, קינוח, תצפית/אטרקציה חינמית)
   או למקום שמקבל walk-in. **מוצר שעובד מקצה לקצה.**
2. **שלב 2, מנוע הזמנות:** תור עבודות, ManualAdapter (טלגרם למפעיל),
   OntopoPlaywrightAdapter, גיבויים, ביטול. נכנסות מסעדות.
3. **שלב 3, חדרי בריחה וסרטים:** חדרי בריחה דרך ManualAdapter, ואחר כך
   מתאמים לאתרים נפוצים. סרטים דרך מתאם לאתרי הרשתות.
4. **שלב 4, תשלומים:** סולק ישראלי (Grow/Cardcom). הלקוח משלם לאפליקציה,
   והאפליקציה משלמת לספק בכרטיס העסק. דורש עסק רשום.
5. **שלב 5, שותפויות:** API רשמי (אונטופו/Tabit), במקום Playwright.

המסמך הזה מאשר את כל הכיוון. **התוכנית המפורטת הראשונה תכסה את שלב 1 בלבד.**

## 8. מה נשאר לבונה

- בחירת ספריות UI ואנימציה, מבנה קבצים, טסטים.
- נוסחת הניקוד המדויקת והמשקלות.
- ניסוח הרמזים והפרומפט ל-Claude (בתוך הטון).
- עיצוב ויזואלי (בתוך: צעיר, כהה/צבעוני, RTL, מובייל).
- מיקום הקוד: **החלטה שלי** — בשלב 1 תיקייה `outing/` על הענף הנוכחי
  בריפו הזה, ומעבר לריפו ייעודי כשהמשתמש יבקש.

## 8א. החלטות לשלב 1 (החלטות שלי, ניתנות לשינוי)

- **פילטרי "לא בשבילי" כשהמידע חסר:** הכלל הוא "בספק — לא". כשר:
  רק מקומות ששמם או המידע עליהם מציין כשרות, ו-Claude מאשר מהתיאור ומהביקורות.
  אם לא בטוח, המקום נפסל. בלי אלכוהול: בלי ברים ובלי מקומות עם
  `servesBeer/servesWine`. טבעוני/צמחוני: `servesVegetarianFood`. נגישות:
  רק מקומות עם שדה נגישות חיובי. אלרגיות: מוצגות כאזהרה בכרטיס המשימה
  ("ציינו במקום"), בלי סינון. רשימה ידנית של מקומות כשרים מאומתים תיבנה בהמשך.
- **אירוח:** בשלב 1 אין Playwright, אז אין צורך ב-VPS. ה-PWA יעלה ל-Cloudflare
  Pages כפרויקט נפרד (origin נפרד מ-Excerly, כדי לא להתנגש ב-sw.js),
  וה-API יהיה Cloudflare Worker נפרד, כמו התשתית הקיימת. ה-VPS ייכנס בשלב 2.
- **מי נכנס:** בטא סגורה עם קוד הזמנה, הגבלת קצב לפי מכשיר ו-IP, ותקרת
  הוצאה יומית בשרת. כשמגיעים אליה מופיעה הודעה "נחזור מחר 😴".
- **קטגוריות שלב 1:** בר, בית קפה, קינוח/גלידה, תצפית/אטרקציה חינמית.
  לא כוללים מסעדות. בקבוצות של 7 ומעלה לא בוחרים בר קטן (פחות מ-200
  ביקורות). השורה "שולחן על השם" וביטול הזמנה לא קיימים בשלב 1.
- **כשאין התאמה:** אף פעם לא מגישים הפתעה מאכזבת. מרפים קודם קריטריונים
  רכים (מרחק, וייב, ואז דירוג עד 4.0), ואם עדיין אין התאמה מוצג מסך כן:
  "אין פה משהו שווה עכשיו, נסו להרחיב את המרחק".

## 9. סיכונים

- חסימה/שבירה של Playwright: גיבויים, ManualAdapter ומעבר לשותפויות.
- עלות Google Places: מטמון (cache) תוצאות לפי אזור, ושדות מינימליים
  (field mask).
- איכות נתונים (שעות פתיחה לא נכונות): בדיקה כפולה בזמן הבחירה ומשוב
  משתמשים.
- פרטיות: מיקום נשלח רק לבקשה הנוכחית ולא נשמר בשרת מעבר ליציאה הפעילה.
